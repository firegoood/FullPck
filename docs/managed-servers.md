# سرورهای مدیریت‌شده

<div dir="rtl">

## خلاصهٔ فارسی

FullPack با Agent خروجی روی سرور خارجی، دو سوی تونل مدیریت‌شده را از پنل کنترل می‌کند. سرور خارجی به آدرس WebUI کنترلر وصل می‌شود؛ کنترلر برای مدیریت Node به IP عمومی سرور خارجی اتصال تازه‌ای برقرار نمی‌کند. این قابلیت پورت مدیریت جداگانه‌ای باز نمی‌کند و پورت 443 را رزرو نمی‌کند. اگر WebUI را عمداً روی 443 تنظیم کنید، خود WebUI از آن استفاده خواهد کرد؛ این انتخاب مستقلی از Fleet و Telegram است.

## افزودن Node

1. FullPack را روی سرور خارجی با `sudo bash install.sh --role kharej` نصب کنید. این کار قبل از ثبت‌نام هم WebUI محلی را خاموش نگه می‌دارد.
2. در پنل کنترلر، از بخش دائمی **Servers** در نوار اصلی، **Add a server** را باز کنید؛ نام Node و آدرس کامل Controller را با پورت WebUI وارد کنید. این بخش حتی پیش از افزودن نخستین Node در دسترس است. آدرس باید از سرور خارجی قابل دسترسی باشد. پنل کد ثبت‌نام را تا خروج از صفحه نشان می‌دهد؛ با **Copy code** کپی کنید یا متن را دستی انتخاب کنید. کد زمان اعتبار محدود دارد.
3. روی سرور خارجی، `sudo fullpack node join` را اجرا و کد را در ورودی تعاملی وارد کنید. کد را در آرگومان فرمان، اسکریپت عمومی یا گزارش‌ها قرار ندهید.
4. Agent در سرویس موجود `fullpack-monitor.service` اجرا می‌شود و به WebUI کنترلر وصل می‌ماند. وضعیت اتصال را در صفحهٔ Servers ببینید.

کد ثبت‌نام فقط یک هویت و اعتبارنامهٔ دائمی جداگانه می‌سازد. کد استفاده‌نشده پس از زمان اولیهٔ خود (در پنل ۱۵ دقیقه) منقضی می‌شود. اگر کنترلر Node را ثبت کرده باشد ولی پاسخ شبکه گم شود یا نوشتن تنظیمات Node شکست بخورد، همان `fullpack node join` را با همان کد روی همان سرور دوباره اجرا کنید؛ اعتبارنامهٔ موقتِ بازیابی در فایل خصوصی `node-agent.json.pending` ثابت می‌ماند. بازیابی دقیق با همان اعتبارنامه از زمان ثبت Node حداکثر ۲۴ ساعت معتبر است؛ کد یا اعتبارنامهٔ متفاوت و Node لغوشده رد می‌شود. پس از ذخیرهٔ موفق تنظیمات، کد تکمیل می‌شود و دیگر برای ثبت‌نام جدید پذیرفته نیست. انقضای مسیر بازیابی فقط کد bootstrap را غیرفعال می‌کند؛ Node ثبت‌شده و اعتبارنامهٔ دائمی آن را حذف یا لغو نمی‌کند. Agent با اعتبارنامهٔ دائمی خود همچنان می‌تواند متصل شود و ثبت‌نام ناتمام را تکمیل کند. فایل intent پس از ذخیرهٔ نهایی یا دریافت پاسخ انقضای کد پاک می‌شود. اعتبارنامهٔ دائمی در کنترلر رمزگذاری و در سمت Node با مجوز `0600` ذخیره می‌شود. اتصال WebSocket با Noise محافظت می‌شود؛ برای HTTPS نیز گواهی معتبر یا pin گواهی هنگام ثبت‌نام بررسی می‌شود.

Node آدرس و پورت WebUI را از کد ثبت‌نام می‌گیرد. اگر پنل روی پورت دیگری مثل 8443 یا 9443 باشد، Agent همان پورت را به کار می‌برد. مسیر `/_bp/node` زیر همان origin پنل قرار دارد و به base path تصادفی رابط کاربری وابسته نیست.

## ساخت و ادارهٔ تونل

در **Tunnels → Add tunnel** حالت **Manual / Local** برای ساخت یک سمت روی همین سرور و حالت **Managed / Paired** برای ساخت هر دو سمت با Node متصل به‌صورت صریح انتخاب می‌شود. Manual حتی با وجود Node آنلاین در دسترس است و اطلاعات لازم برای تکمیل سمت دیگر را نشان می‌دهد. عملیات Agent محدود به درخواست‌های مشخص مانند خواندن وضعیت، اعمال تنظیمات تونل، شروع/توقف/راه‌اندازی دوباره و دریافت لاگ است. اجرای فرمان دلخواه یا shell از طریق این کانال وجود ندارد.

**Servers → Check the fleet** وضعیت تونل‌های Node را با وضعیت مورد انتظار مقایسه می‌کند. قطع اتصال Agent به معنی حذف یا توقف تونل‌های موجود روی آن سرور نیست. عملیات مدیریتی تا اتصال دوباره در دسترس نخواهد بود.

تونل دستی همچنان مستقل است: بدون افزودن Node می‌توانید دو سوی reverse یا direct را با دستورها و لینک‌های معمول راه‌اندازی کنید.

## حذف دسترسی و به‌روزرسانی

Revoke اعتبارنامهٔ Node را در کنترلر غیرفعال و جلسهٔ فعالش را قطع می‌کند. Remove رکورد Node را از فهرست حذف می‌کند؛ سرویس‌های تونل موجود روی آن سرور را پاک نمی‌کند. برای نصب و به‌روزرسانی خود FullPack روی Node از مسیر نصب/به‌روزرسانی تأییدشدهٔ محلی همان سرور استفاده کنید.

## Telegram و پورت 443

در حالت Automatic، ربات Telegram ابتدا از Agent متصل برای انتقال بایت‌های TLS به **مقصد خارجی** `api.telegram.org:443` استفاده می‌کند. توکن و منطق ربات در مانیتور کنترلر می‌مانند و ارتباط TLS تا Telegram ادامه دارد. ارتباط داخلی مانیتور با کنترلر از Unix socket محدود `/run/fullpack/control.sock` است؛ هیچ listener محلی روی 443 برای Telegram ساخته نمی‌شود.

اگر Agent در دسترس نباشد، مسیر تونل موجود می‌تواند fallback باشد. این مسیر یک پورت بلند تصادفی فقط روی `127.0.0.1` برای ارسال به همان مقصد می‌سازد. نگاشت قدیمی Telegram روی پورت محلی 443 هنگام آماده‌سازی به پورت بلند منتقل می‌شود. اگر WebUI خاموش باشد، Telegram می‌تواند از fallback تونل استفاده کند.
