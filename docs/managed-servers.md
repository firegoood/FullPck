# سرورهای مدیریت‌شده

<div dir="rtl">

## خلاصهٔ فارسی

BackPack با Agent خروجی روی سرور خارجی، دو سوی تونل مدیریت‌شده را از پنل کنترل می‌کند. سرور خارجی به آدرس WebUI کنترلر وصل می‌شود؛ کنترلر برای مدیریت Node به IP عمومی سرور خارجی اتصال تازه‌ای برقرار نمی‌کند. این قابلیت پورت مدیریت جداگانه‌ای باز نمی‌کند و پورت 443 را رزرو نمی‌کند. اگر WebUI را عمداً روی 443 تنظیم کنید، خود WebUI از آن استفاده خواهد کرد؛ این انتخاب مستقلی از Fleet و Telegram است.

## افزودن Node

1. BackPack را به روش معمول روی سرور خارجی نصب کنید.
2. در پنل کنترلر، **Servers → Add a server** را باز کنید و نام Node را وارد کنید. پنل کد ثبت‌نام یک‌بارمصرف با زمان اعتبار محدود می‌دهد.
3. روی سرور خارجی، `sudo backpack node join` را اجرا و کد را در ورودی تعاملی وارد کنید. کد را در آرگومان فرمان، اسکریپت عمومی یا گزارش‌ها قرار ندهید.
4. Agent در سرویس موجود `backpack-monitor.service` اجرا می‌شود و به WebUI کنترلر وصل می‌ماند. وضعیت اتصال را در صفحهٔ Servers ببینید.

کد ثبت‌نام فقط یک بار پذیرفته می‌شود. بعد از ثبت‌نام، یک شناسه و اعتبارنامهٔ دائمی جداگانه برای همان Node ساخته می‌شود. اعتبارنامه در کنترلر رمزگذاری و در سمت Node با مجوز محدود ذخیره می‌شود. اتصال WebSocket با Noise محافظت می‌شود؛ برای HTTPS نیز گواهی معتبر یا pin گواهی هنگام ثبت‌نام بررسی می‌شود.

Node آدرس و پورت WebUI را از کد ثبت‌نام می‌گیرد. اگر پنل روی پورت دیگری مثل 8443 یا 9443 باشد، Agent همان پورت را به کار می‌برد. مسیر `/_bp/node` زیر همان origin پنل قرار دارد و به base path تصادفی رابط کاربری وابسته نیست.

## ساخت و ادارهٔ تونل

از **Tunnels → Add tunnel** می‌توانید Node متصل را برای انتهای دیگر انتخاب کنید و تنظیمات هر دو سمت را از پنل اعمال کنید. عملیات Agent محدود به درخواست‌های مشخص مانند خواندن وضعیت، اعمال تنظیمات تونل، شروع/توقف/راه‌اندازی دوباره و دریافت لاگ است. اجرای فرمان دلخواه یا shell از طریق این کانال وجود ندارد.

**Servers → Check the fleet** وضعیت تونل‌های Node را با وضعیت مورد انتظار مقایسه می‌کند. قطع اتصال Agent به معنی حذف یا توقف تونل‌های موجود روی آن سرور نیست. عملیات مدیریتی تا اتصال دوباره در دسترس نخواهد بود.

تونل دستی همچنان مستقل است: بدون افزودن Node می‌توانید دو سوی reverse یا direct را با دستورها و لینک‌های معمول راه‌اندازی کنید.

## حذف دسترسی و به‌روزرسانی

Revoke اعتبارنامهٔ Node را در کنترلر غیرفعال و جلسهٔ فعالش را قطع می‌کند. Remove رکورد Node را از فهرست حذف می‌کند؛ سرویس‌های تونل موجود روی آن سرور را پاک نمی‌کند. برای نصب و به‌روزرسانی خود BackPack روی Node از مسیر نصب/به‌روزرسانی تأییدشدهٔ محلی همان سرور استفاده کنید.

## Telegram و پورت 443

در حالت Automatic، ربات Telegram ابتدا از Agent متصل برای انتقال بایت‌های TLS به **مقصد خارجی** `api.telegram.org:443` استفاده می‌کند. توکن و منطق ربات در مانیتور کنترلر می‌مانند و ارتباط TLS تا Telegram ادامه دارد. ارتباط داخلی مانیتور با کنترلر از Unix socket محدود `/run/backpack/control.sock` است؛ هیچ listener محلی روی 443 برای Telegram ساخته نمی‌شود.

اگر Agent در دسترس نباشد، مسیر تونل موجود می‌تواند fallback باشد. این مسیر یک پورت بلند تصادفی فقط روی `127.0.0.1` برای ارسال به همان مقصد می‌سازد. نگاشت قدیمی Telegram روی پورت محلی 443 هنگام آماده‌سازی به پورت بلند منتقل می‌شود. اگر WebUI خاموش باشد، Telegram می‌تواند از fallback تونل استفاده کند.

برای جزئیات پایدار معماری، امنیت و آزمون‌ها، [مشخصات شخصی‌سازی](CUSTOMIZATION_SPEC.md) را ببینید.
